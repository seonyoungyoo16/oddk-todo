# UX09 목록·시간표 이동

상태: 자체 QA·실제 계정 왕복 완료. 최종 CI·배포·운영 인수 대기. 실제 OAuth·실물 단말·200% 확대는 UX13에서 별도 인수한다.

## 범위와 계약

- 목록은 수동 순서 모드에서만 손잡이를 제공한다. 보이는 항목의 슬롯끼리 이동하고 필터에 숨긴 항목의 위치·내용은 보존한다. 기존 위/아래 버튼은 키보드·터치 대안으로 유지한다.
- 시간표 손잡이는 세로 이동 거리를 기존 3px/분 눈금에 맞춰 5분 단위 변경안으로 변환한다. 놓는 즉시 저장하지 않고 원래/새 날짜·시각, 작업·여유·총시간, 겹침과 활동 밖 경고를 팝업에서 확인한다.
- 짧은 구간과 키보드 사용자는 시간 이동 버튼에서 날짜·시각 입력 및 ±15분/±하루 버튼을 사용한다. 작은 구간용 보조 손잡이도 제공한다.
- 시간 이동 버튼의 첫 제안은 15분 뒤다. 변경 전/후 값을 명시하고 사용자가 바꾸거나 취소할 수 있다. 완료·요약·시간 미설정 항목과 고정/휴식은 이동 대상이 아니다.
- 작업·여유 분, 업무 ID·내용·중요도·분류·목표 연결을 보존한다. 자정 넘김은 새 종료 날짜를 계산해 보여준다. 날짜 범위 밖·중복 업무는 거부한다.
- 이동 시작 때 계획과 적용 직전의 계획이 다르면 거부하고 다시 확인한다. 확인 도중 다른 기기 변경을 덮지 않는다. 계정 전환은 기존 workspace key 경계로 이동 팝업을 해제한다.
- 모든 확정 변경은 기존 save/undo/동기화 경로를 사용한다. 저장 실패는 계획을 확정하지 않고 변경안을 유지한다. Escape·취소·포인터 취소·목록 밖 놓기는 변경하지 않는다.
- 새 schema·DB·Auth 설정은 필요 없다. Google·GitHub는 활성 상태를 유지한다.

## ALPEN과 타임블로킹

A: 목록 이동/시간 이동/실패·복구/계정 왕복/배포로 나눈다. L: 한 집중 블록50분. P: 수정·재시험15분. E: 데이터 보존→조작 동등성→충돌·경계→접근성 순으로 확인한다. N: 블록마다 실제 결과와 남은 인수를 갱신한다. 대기 시간은 별도이며 이 문서의 블록은 완료 시간 보장이 아니다.

## 인수·QA

- [x] 필터가 있는 목록의 드래그 도착 순서와 버튼 결과가 같고 숨긴 위치와 undo를 보존한다. (공통 로직 단위시험)
- [x] 날짜/시각 이동이 작업·여유·종료 날짜·목표를 보존하고 자정·윤일·연말·달력 상한을 검증한다. (단위시험)
- [x] 숨긴 일정·고정 시간·활동 밖·다음 날짜 충돌을 전체 계획으로 계산한다. 인접 일정은 겹침이 아니다. (단위시험)
- [x] 낡거나 변조된 미리보기, 완료 업무, 같은 업무 중복 이동을 거부한다. (단위시험)
- [x] 실제 포인터 드래그와 위/아래 버튼의 순서 결과, 취소·영역 밖 놓기·정렬 전환을 확인한다.
- [x] 시간표 드래그와 날짜·시각/버튼 입력을 동일 결과로 확인하고 승인/취소/실행 취소를 시험한다.
- [x] 저장 실패·동시 계획 변경·다른 계정 전환 시 계획과 변경안의 보존을 확인한다.
- [x] 실제 계정 두 개로 순서·날짜·시간 왕복과 CAS/계정 격리를 확인하고 시험 자료를 정리한다.
- [x] 키보드·팝업 포커스·모바일·다크·짧은 구간에서 손잡이와 대체 조작을 확인한다.
