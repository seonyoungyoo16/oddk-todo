# UX08 이동 시간 제안 시제품

상태: 구현 중 / UX07 배포 게이트 완료 후 착수 / 운영 미배포

## 사용 흐름

오늘 계획 안의 접힌 ‘여행 이동 계획’에서 날짜·출발 시각·이동 수단과 방문 순서(출발 포함 2~6곳)를 입력한다. 장소 검색은 버튼으로만 요청하고 후보의 이름·지역을 보고 직접 선택한다. 각 도착지의 체류 시간은 사용자가 여유 포함 값으로 직접 입력한다. 체류 없이 다음 장소로 가려면 0분을 명시한다.

경로 조회→구간별 이동 시간·출처·조회 시점 확인→직접 보정→전체 시간표 미리보기→승인 후 할 일에 추가한다. 조회·초안·미리보기만으로 계획을 바꾸지 않는다. 결과가 없거나 잘못된 장소이면 이름과 이동 시간을 직접 입력해 계속한다. 직접 정한 이동 시간은 재조회해도 유지한다.

## 서비스와 한계

- 장소: [Photon 공개 데모](https://github.com/komoot/photon#demo-server). 합리적인 소규모 사용만 허용하며 과도한 호출은 제한/차단될 수 있고 가용성 보장이 없다. 공개 Nominatim API는 사용하지 않는다. 별도 API 키/유료 계약은 초기 시제품에 필요 없다.
- 경로: [FOSSGIS OSRM](https://routing.openstreetmap.de/about.html). 자동차·도보·자전거는 운영자 설정의 routed-car/routed-foot/routed-bike 각각을 사용한다. 경로 요청은 1초당1회 이하, 식별 가능한 User-Agent·출처 표시·지도 수정 링크를 제공한다. 실시간 교통/출발 시각별 혼잡/대중교통 조회로 표현하지 않는다.
- 출발 날짜·시각은 조회한 정적 이동 시간을 일정에 배치하는 기준이다. 출발 조건이 다른 실시간 예측값처럼 표시하지 않는다. 마사지/관광 체류 시간을 자동 추정하지 않는다.
- 서버 proxy에서 외부 호출 전체를 공급자당 최소1.2초 간격·한국 날짜 기준 하루200회로 제한한다. 다중 Edge 인스턴스에도 DB의 원자적 갱신으로 제한한다. 버튼 잠금만으로 전체 호출 제한을 대체하지 않는다.
- 검색은 최대5개 후보, 경로는 최대6곳/5구간, 본문4KiB, 외부 대기10초. 응답을 검증한 뒤 검색7일/경로24시간 캐시하며 실제 조회 시점을 유지한다. 실패 응답을 정상 결과로 캐시하지 않는다.
- 공개 장소 검색어·선택 좌표가 Photon/FOSSGIS로 전달됨을 조회 전에 안내한다. 개인 주소나 위치 권한을 요구하지 않는다. 공개 관광지 예제로 검증한다. DB 캐시에는 원시 검색어 대신 해시 키와 제한한 공개 조회 결과만 저장하며 클라이언트의 직접 접근은 허용하지 않는다.
- 서버 환경 설정으로 공급자를 중단·교체할 수 있게 어댑터를 분리한다. 초기 서비스 중단 시 수동 입력 대안을 유지한다. 운영 규모가 커지면 유료/자체 호스팅 선택은 마지막 사용자 결정 목록으로 넘긴다.

## 시간·저장 계약

- 이동 작업 시간=조회 seconds를 분으로 올림(최소1분) 또는 직접 입력. 여유는 사용자가 별도로 정하고 이동 수행=작업+여유이다.
- 체류 입력은 여유 포함 수행 시간이다. 예: 체류60/여유10이면 작업50. 이동·방문 모두 기존2~240분/양수 여유 규칙을 따른다. 초과 구간을 조용히 줄이지 않는다.
- 자정을 넘으면 시작/종료 날짜를 계산한다. 잘못된 날짜·부분 입력·달력 상한·미확정 체류는 미리보기를 막고 초안을 유지한다.
- 생성 업무는 기존 Task 필드로 저장하고 출처·모드·실조회 시점·직접 보정 여부를 notes에 기록한다. 계정별 로컬 여행 초안은 동기화 계획에 넣지 않는다. 스키마5와 기존 목표·업무를 보존한다.
- 여행ID+장소ID별 고정 업무ID로 반복 승인 중복을 막는다. 이미 반영한 업무는 재조회로 수정하지 않는다. 미리보기 이후 입력이 바뀌거나 항목을 위조하면 적용을 거부한다. 추가 전체를 한 번의 저장/undo로 처리한다.
- 반영 전 기존 일정·고정 시간과의 충돌을 날짜별로 확인할 수 있어야 한다. 충돌을 숨기거나 자동 이동하지 않는다.

## ALPEN·타임블록

A: 조회 계약/제한 서버, 입력·후보 선택, 미리보기·일정 반영, 실제 조회·사용성 비교, 배포를 분리한다. L: 각 작업은 집중50분 단위로 나누고 실제 시간을 기록한다. P: 블록당 수정·재검증15분, 외부 서비스 대기는 별도다. E: 데이터 보존·실제 조회부터 검증하며 유료 연결은 뒤로 미룬다. N: 관련 Q22와 단계 완료 조건을 근거별로 기록하고 Pages 검증 전 UX09를 시작하지 않는다.

## 유용성 비교의 사전 기준

동일한 공개 관광지 3곳·이동 수단·출발 시각·체류 값으로 ‘서비스별 경로 검색 후 수동 등록’과 ‘시제품 조회 후 승인’을 비교한다. 측정 시작은 빈 입력, 종료는 동일한 이동/방문 일정이 저장된 시점이다. 사용자 입력/클릭 단계·활성 작업 시간·서비스 대기·잘못 고른 장소·시간 수정 횟수를 각각 기록한다. 합성 응답 시험과 실제 조회 결과를 구분한다.

확대 후보 기준: 계획/출처 누락0, 중복0, 성공한 예제에서 입력 단계30% 이상 절약, 잘못된 후보를 자동 확정하지 않음. 작성 시간은 실측해 보고한다. 비교가 실패하면 수정/중단 이유를 남기고 API 연결만으로 완료 처리하지 않는다. 에이전트 자체 비교는 독립 사용자 사용성 검증과 구분해 후자는 UX13에 남긴다.

## 구현 중 확정한 보완

- 호출권은 공급자별 DB lease로 잡고 외부 응답 처리 후1.2초 쉬게 한다. 동시 Edge 인스턴스의 호출이 겹치지 않으며 유효2초 이내에 시작하지 못한 권한은 사용하지 않는다. 소유 lease만 해제하고 비정상 종료 시15초 후 회복한다. 오류·timeout도 호출 예산에 포함한다.
- 서버 환경 변수 TRAVEL_LOOKUP_DISABLED=true로 중단하고, 교체는 서버 어댑터를 배포해 수행한다. 클라이언트에 임의 외부 URL을 받지 않는다. 브라우저 대기는20초로 제한하고 이동/계정 전환 시 요청을 취소한다.
- 직접 입력 시간을 구간 조건(앞/뒤 장소·순서·수단)에 연결한다. 조건이 바뀌면 값을 남겨두고 현재 구간에 쓸지 재확인한다. 재조회만으로 직접 입력을 덮지 않는다.
- 다른 날짜의 같은 여행에서 기존 전역 제목 중복 검사가 undo를 막는 결함을 재현했다. 중복 판단을 제목+계획 날짜+시작 시각으로 통일한다. 날짜·시각이 다르면 같은 제목을 허용하고, 같은 날짜·시각의 동일 일정은 중복 승인/등록으로 막는다. 메모함의 날짜·시각 없는 같은 제목 중복 방지는 유지한다. 실제 업무 ID의 유일성은 별도 불변식이다.
