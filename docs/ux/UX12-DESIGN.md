# UX12 남은 시간 재조정

상태: UX11 같은 SHA 운영 게이트 완료 후 착수. 사용자 승인 없이 계획을 바꾸지 않는다.

## 사용자 흐름과 범위

- 오늘 계획에서 ‘남은 시간 재조정’ → 시작 기준(비우면 현재 시각 다음 분)과 움직이지 않을 일 확인 → 미리보기 → 변경/보호/미배치와 사유 확인 → 명시적 승인. 닫기/취소는 계획에 영향이 없다.
- 현재 필터와 관계없이 오늘의 미완료 실행 업무 전체를 대상으로 한다. 날짜 없는 일·다른 날짜·완료·요약 업무와 전날부터 이어지는 구간을 바꾸지 않는다. 오늘 끝나지 않는 일은 자동으로 내일에 넘기지 않는다.
- 기본 보호: 미래에 이미 배치한 일정. 사용자가 보호를 해제하면 재배치 대상이 된다. 활동 시간의 고정·휴식 구간은 항상 보호한다. 보호 업무와 고정/보호 업무가 남은 구간에서 겹치거나 활동 시간 밖이면 먼저 직접 고치게 한다.
- 작업/여유/수행 시간·마감·중요도·우선순위·분류·메모·목표는 그대로다. 마감 빠른 순→중요도→우선순위→기존 수동 순으로 연속 빈 구간에 배치한다. 긴 일을 임의 분할하거나 짧게 만들지 않는다.
- 마감 지남, 시간 미설정, 연속 구간 부족, 마감 전 완료 불가를 구별한다. 배치하지 못한 대상의 기존 시작/종료를 해제하는 경우도 미리보기에서 명시하고 수행/여유 예상값과 날짜는 남긴다. 보호 업무는 그대로다.
- 미배치로 시각을 해제하면 시작 시각에 의존하는 알림도 해제한다는 사실을 변경 목록에 표시한다. 반복의 다른 날짜나 원본 알림 규칙은 유지한다.
- 실제 작업 기록이 열려 있으면(일시정지 포함) 먼저 기록을 종료하도록 안내하고 재조정을 막는다. 현재 업무가 언제 끝나는지 임의로 추측하지 않는다. 종료한 실적은 계획에서 자동 차감하지 않으며 남은 소요시간 수정이 필요하면 사용자가 먼저 수정한다.
- 적용 후 기존 최근 변경 실행 취소로 돌아갈 수 있다. 반복은 해당 날짜만 예외로 표시하며 원본 규칙/다른 발생일·완료 이력을 바꾸지 않는다.

## 저장과 경쟁 요청

- 미리보기는 현재 계획 원문, 실제 기록 revision, 기준 분/날짜/보호 ID와 생성한 변경안을 고정한다. 적용 전에 현재 계획/기록과 비교하고 이미 지난 새 시작 시각이면 다시 미리보기를 요구한다.
- 비로그인은 Web Locks로 시간 기록 조작과 재조정을 직렬화하고 native IndexedDB에서 열린 기록/revision을 다시 확인한 뒤 현재 localStorage 계획을 비교해 저장한다. 지원하지 않으면 재조정만 명시적으로 안내하며 기존 계획/기록을 유지한다. 계획/기록 백업을 섞지 않는다.
- 로그인은 기존 plan-sync의 별도 replan 요청을 사용한다. 최신 서버 계획과 공통 알고리즘으로 변경안을 다시 계산해 사용자가 승인한 계획과 구조 비교한다. DB RPC는 계획→실행 state를 잠근 뒤 두 버전/열린 기록 없음/첫 배치가 현재 이후임을 한 트랜잭션에서 검사한다. 일반 계획 저장은 그대로 둔다.
- 계정 재조정은 온라인 확인 후 반영한다. 원안/변경안을 먼저 기기에 백업하고 서버 결과를 확인한다. 응답 유실 시 서버 계획/버전을 다시 읽어 동일 변경 확인 또는 미확정을 구분한다. 중간에 계정/기기 계획이 바뀌면 덮지 않고 원안/변경안과 최신 내용을 보존한다.
