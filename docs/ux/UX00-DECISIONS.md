## 데이터 이전·복구 설계

- UX01은 별도 oddk.drafts.v1.<scope> 키에 로컬 UI 초안만 저장하므로 계획 V2/Edge 변경이 필요 없다. 로그인 identity의 scope와 UI workspace key를 재사용한다.
- UX02부터 영속 메모 등 새 필드를 도입할 때 계획 V3를 명시한다. 타입·공통 검증·이전기·Edge·브라우저 캐시·백업·통합시험을 같은 출시 묶음에 넣는다. V3를 V2 데이터인 것처럼 쓰지 않는다.
- V1→V2→V3 순서로 순수 이전한다. ID/날짜/시간/완료/기존 목표/점검/legacy priority 보존. 새 속성은 문서의 기본값만 채운다. 기존 업무가 갑자기 오늘로 배정되지 않는다.
- 이후 기능 필드는 V3의 선택 속성으로 확장하되 알 수 없는 내용을 제거하지 않게 계획 전체를 보존한다. 새로운 필수 계약이나 의미 변경은 다음 schemaVersion으로 올린다. UI 모델만 바꾸고 검증기/서버를 뒤에 두지 않는다.
- 서버는 새 형식 쓰기 전에 먼저 구/신형 읽기·검증을 지원해야 한다. 서버에 V3가 저장된 계정에 V1/V2 쓰기가 오면 CAS 검증과 별도로426 거부한다. 기존 클라이언트가 새 필드를 제거하지 못하게 한다.
- 이전 전 원문 .before-v3, 마지막 유효본, dirty outbox, 충돌 반대쪽 백업을 분리한다. 손상/미래 형식은 빈 계획으로 대체하지 않는다. 요청1MB 한도 유지하고 경계 오류를 안내한다.
- 전체 JSON CAS 충돌은 기존 양쪽 비교·선택을 유지한다. 서로 다른 날짜도 자동 합치지 않는다. 초안은 확정 계획과 별도라 충돌 처리로 지우지 않는다.
- 실행 취소는 현재 변경과의 일치 확인 후 목표 참조까지 복구한다. 이미 원격에서 달라진 항목은 덮지 않고 선택을 안내한다.
- 롤백은 해당 형식을 읽고 보존할 수 있는 릴리스만 사용한다. 안전하지 않으면 쓰기 중지, 원문 보존·호환 버전 배포 후 복구한다. V3→V2 자동 역변환은 하지 않는다.

## 시안과 사용자 흐름

정적 비기능 시안: UX00-WIREFRAME.html. 실제 계획을 저장하지 않으며 예시임을 표시한다.

1. 날짜 띠에서 오늘/다른 날짜 선택 → 해당 날짜의 추가 입력에서 등록(시간은 나중 설정 가능).
2. 업무 클릭 → 시작/종료/여유, 중요도·목표 연결 → 저장 → 같은 ID가 목록과 시간표에 반영.
3. 목표 보기 → 핵심·세부·업무 확인 → 해당 업무 상세로 바로 이동, 날짜 문맥 유지.
4. 모바일은 같은 날짜/필터를 유지하며 목록/시간표 보기 전환, 합계와 등록은 기본 노출.
