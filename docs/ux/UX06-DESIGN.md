# UX06 중요도·마감·순서·일괄 선택 계약

상태: UX06 UI·서버9·자체 QA 완료, PR/Pages 배포 게이트 대기. 결과는 UX-PROGRESS.md 참조.

- 중요도는 새 선택 필드 high/normal/low이며 기존 데이터는 normal로 표시한다. 기존 priority는 별도로 보존하고 자동 변환하지 않는다.
- 마감은 선택 날짜와 선택 시각이다. 시각만 저장하지 않는다. 날짜만 있으면 그 날짜가 끝나는 한국 자정에 마감한다. 계획 시작/종료와 별도이며 시간이 넘어도 계획을 자동 이동하지 않는다.
- 중요도/마감 정렬은 표시만 바꾸며 같은 값은 저장 순서를 유지한다. 미완료를 먼저 표시하고 마감 없음은 마감 정렬의 뒤에 둔다. 번호는 현재 표시 순서다.
- 수동 순서는 기존 Plan.tasks의 ID 순서를 기준으로 보존한다. 별도 중복 순서 필드를 만들지 않는다. 수동 보기에서 이동하면 보이는 ID가 있던 자리만 교환하므로 숨긴 업무의 위치·시간·연결은 유지한다. 위/아래 버튼을 먼저 제공하고 드래그는 UX09에서 연결한다.
- 선택 ID는 계정별 로컬 초안에 보관한다. 날짜·상태·분류·검색·보기 이동에 유지한다. 전체 선택은 현재 보이는 항목의 선택만 바꾸며 숨긴 선택을 지우지 않는다.
- 일괄 처리 전 전체/화면 내/숨긴 선택 개수와 대상 제목·날짜를 확인한다. 선택 해제와 처리 취소를 제공하며 완료·삭제는 같은 ID만 변경한다. 원격에서 삭제된 선택은 처리하지 않고 개수를 별도 안내한다. 다른 계정의 선택은 섞이지 않는다.
- 완료 취소로 동일 제목 미완료가 중복되면 기존 중복 방지 규칙으로 거부한다. 모든 변경은 기존 CAS·저장실패·실행 취소를 유지한다.

검증 게이트: 단위/공통 Deno → 실제 전용 계정 왕복·잘못된 마감400 원본 보호·CAS → 날짜/필터 숨긴 선택·정렬·이동·undo 브라우저 → 모바일/키보드 → PR CI → 동일SHA Pages와 운영 확인. 사용자 실제 OAuth/단말 확인은 최종 인수에 남긴다.
