## 수동 작성 대비 관측

같은 공개 여행 과제에서 ID를 제외한 제목·계획 날짜·시작·종료 날짜/시각·총시간·여유·메모·완료9개 필드를 비교했다. 수동 방식에도 실제 조회 결과와 메모 원문을 미리 제공해 외부 검색 시간을 제외했다. 두 유효 측정 모두4개 일정의 값이 정확히 일치했고 기존 목표·원본 만다라트는 보존됐다.

| 항목 | 수동 등록 | 시제품 |
|---|---:|---:|
| 필드 입력/선택·버튼·키 조작 단위 | 32 | 20 |
| 관측 경과 시간 | 47.098초 | 64.231초 |
| 잘못 선택한 장소/내용 수정 | 0/0 | 0/0 |
| 결과 누락·중복 | 0/0 | 0/0 |

수동은 각 일정마다 제목·Enter·수정창·메모·시작·종료·여유·저장8단위×4였다. 시제품은 패널/작성2, 출발·여유·수단3, 장소 입력·검색·후보 선택9, 방문 추가1, 체류2, 경로 조회·미리보기·승인3으로20단위였다.

조작 단위는 **37.5% 감소**해 사전에 정한30% 기준을 충족했다. 반면 관측 경과 시간은17.133초 늘었다. 이 시간에는 에이전트 도구·판단·화면 관측 대기가 포함되고 시제품 조회는 캐시를 사용했다. 사람의 입력 속도나 실제 여행 계획 소요 시간의 개선을 입증하지 않는다.

첫 수동 측정은 자동화 도구의 시각 입력이 변경을 확정하지 못해1개만 작성한 불완전 시도(129.224초/11단위)로 제외했다. 기본 입력 방식으로 재측정했으며 제외 기록도 [원본 결과](evidence/UX08-usability.json)에 남겼다. 입력 단위는 의미상 조작이며 물리적인 마우스 클릭·키 타수와 다르다.

## 판단과 정리

**작은 공개 시제품은 유지하고 범위 확대는 보류한다.** 입력·수식 계산·메모 복사의 수고는 줄었지만, 속도 우위나 실제 혼잡 예측의 유용성은 증명되지 않았다. 현재는 정적 경로 제안+사용자 체류·여유 설정 범위를 유지한다. 일반 사용자 실측과 장소 검색 품질을 확인한 뒤 자동 최적화·유료 공급자·대중교통 확장을 검토한다.

브라우저 시험 종료 시 업무0/여행초안null/수정초안0/선택0을 확인했다. 최초 시험 전 계획과 비교하여 업무 외 모든 필드(목표·원본·활동 설정 포함)가 동일함을 정렬 비교로 검증했다. 라이트·선택 해제, 임시 QA HTML·시험 표시·계정 fixture를 정리했다. UI에서 실제 데이터를 초기화하지 않았다.
