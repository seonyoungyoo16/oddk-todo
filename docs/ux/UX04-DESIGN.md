# UX04 시작·종료 시간 계약과 이전 설계

2026-10-28 · 설계/준비 상태. 아래 내용은 구현·시험·배포 완료를 뜻하지 않는다.

UX03 시간표 직접 수정의 추가 회귀 배포 게이트를 마친 뒤 구현한다. 기존 계획의 ID·날짜·시작 시간·수행/여유·메모·목표 연결·점검을 보존한다.

## 입력과 계산

- 기본 입력은 시작 시각, 종료 시각, 종료 날짜, 포함된 여유다. 작업 시간은 계산 결과로 보여준다.
- `09:00~10:00 / 여유10분 → 수행60분 = 작업50분 + 여유10분`이다. 종료 뒤에 여유를 다시 더하지 않는다.
- 날짜가 있는 일정은 종료 날짜를 명시한다. 같은 날 기본값을 보여주며 앞선 종료 시각을 다음 날로 자동 해석하지 않는다.
- 날짜 없는 메모도 계속 허용한다. 날짜 없는 시간 계획은 시간표에 배치하지 않으며 같은 날/다음 날 종료 여부를 명시한다. 이는 기존 V1에서 시작 시각만 있던 메모의 보존에도 필요하다.
- 시각을 아직 모르는 일은 보조 선택인 ‘소요시간만’으로 작업·여유를 먼저 예상할 수 있다. 기존의 시각 없는 소요시간을 강제로 지우거나 날짜에 배치하지 않는다.
- 여유는 유효한 수행 시간이 정해진 뒤 입력 가능하다. 부분 입력은 초안으로 보존하고 확정 저장은 막는다.
- 기존 수행2~240분, 작업1분 이상, 여유1분 이상·수행 미만을 유지한다. 숫자·날짜·시각의 오류는 같은 순수 계약을 브라우저와 서버에서 검증한다.

## 계획 형식 V4

명시적 종료 정보를 새 필수 계약으로 도입하므로 V3를 재해석하지 않고 V4로 올린다. V1/V2/V3 읽기는 유지한다.

- Task에 `endTime`, `endDate`, `endDayOffset`을 둔다. 시작 시각이 없으면 모두 null이다.
- 시작 시각이 있으면 종료 시각과 0/1의 일수 차이를 명시하고 `minutes = 종료분 - 시작분 + 일수차×1440`이 성립해야 한다.
- 계획 날짜가 있으면 종료 날짜가 계획 날짜+일수차와 같아야 한다. 날짜 없는 시간 계획은 종료 날짜도 null이며 일수 차이로 의미를 보존한다.
- 시간 미설정은 minutes/bufferMinutes가 null이다. 시각 없이 소요시간만 있는 값은 두 시간은 유효하고 시작·종료 정보는 null이다.
- 날짜별 활동 설정은 선택 필드로 두고 기본09:00~18:00임을 표시한다. 활동 시작/끝과 고정·휴식 구간을 포함한다. 설정은 해당 날짜에 적용한다.
- 고정·휴식은 별도 일정 차단 구간이며 업무 개수·완료율에 넣지 않는다. 이후 이동 일정과 고정 업무도 같은 가용 구간 계산을 사용한다.

## 이전과 호환

1. 순수 V1→V2→V3→V4 변환으로 기존 수행·여유·시작을 사용해 종료 정보를 산출한다. 기존 일정의 길이를 바꾸지 않는다.
2. 날짜 없는 기존 시작 시각도 유지하고 계산한 종료 시각·일수 차이를 보존한다. 날짜는 임의로 오늘로 채우지 않는다.
3. 9999년을 넘어 유효한 종료 날짜를 만들 수 없는 기존 자료는 원문을 보존하고 명확한 복구 안내를 한다. 조용한 잘림·연도 추정·일정 삭제를 하지 않는다.
4. 원문 `.before-v4`를 먼저 보존한 뒤 로컬 계획·계정 캐시를 바꾼다. V1/V2/V3 백업과 dirty outbox도 유지한다.
5. 서버는 V4 검증을 먼저 지원한다. V4 저장 계정에 V1/V2/V3 쓰기가 오면 버전 조건과 함께426으로 거부한다. 인증·RLS·CORS를 완화하지 않는다.
6. 기존 수정 초안과 실행 취소 기록의 Task 기준값도 같은 순수 변환으로 비교한다. 새 종료 필드만 추가됐다는 이유로 실제 수정 충돌로 오인하지 않게 한다. 초안의 미완성 문자열은 임의 계산·폐기하지 않는다.
7. 배포 롤백은 V4를 읽고 보존할 수 있는 버전으로만 한다. V3 앱을 재배포해 V4를 덮지 않는다.

## 하루 범위와 가용 시간

- 일정 구간은 시작 포함·종료 제외다. 09~10시와10~11시는 겹침이 아니다.
- 자정을 넘는 일정은 각 날짜의 시간표에서 해당 날짜 구간만 표시한다. 시작 날짜/전날에서 이어짐/다음 날 계속됨을 표시한다. 실제 수정 대상은 표시용 사본이 아닌 원래 Task ID다.
- 날짜별 합계는 그 날짜에 속하는 작업·여유 구간을 계산한다. 여러 날짜를 합쳐도 동일한 분이 두 번 계산되지 않아야 한다.
- 구분할 값: 계획 시간의 단순 합계, 일정 겹침을 제거한 점유 시간, 고정·휴식 제외 활동 가능 시간, 아직 비어 있는 시간대, 시간이 있지만 미배치인 업무.
- 충돌은 필터로 숨긴 업무도 포함해 전체 일정으로 계산한다. 서로 겹친 업무 이름·시간대와 고정/휴식 겹침을 알려주고 기존 업무를 자동 이동하지 않는다.
- 단순 합계와 실제 빈 구간은 서로 대체할 수 없다. 겹침이 생겼다는 이유로 늘어난 빈 구간을 ‘추가로 할 수 있는 업무량’처럼 단정하지 않는다.
- 완료 업무는 현재 시간표·미완료 계획 요약에서 제외하되 완료 포함 분석에서는 정한 분량을 유지한다. 실제 소요 시간은 UX11 전까지 표시하지 않는다.

## 구현 묶음과 인수 증거

1. 공통 계약·V4 이전·구버전 거부·회귀 단위시험.
2. 별도 시험 계정에서 실제 서버 V4 저장·읽기·잘못된 끝 시각 거부·CAS 충돌·하위 버전 거부. 실제 사용자 자료는 조회/변경하지 않는다.
3. 초안과 실행 취소 이전, 시작/종료 입력 UI, 날짜 이동·자정 시간표·가용 시간 요약.
4. 브라우저 입력·저장·새로고침·undo·모바일·실패/복구 QA.
5. CI와 Pages 동일SHA 배포·운영 확인 뒤 UX05로 진행한다.

필수 사례: 09~10시/여유10분, 240분 경계, 여유0/수행과같음, 부분/음수/소수, 종료가앞섬, 같은날/다음날 명시, 월말·연말·윤일·9999년 경계, 23:50~다음날00:20, 날짜 없는 기존 시간, 날짜만 있는 업무, 겹침/연속/숨긴 일정/고정휴식, 구 초안·undo·오프라인 outbox 이전과 원문 복구.
