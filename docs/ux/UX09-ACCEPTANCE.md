## 수정하고 재시험한 결함

- StrictMode effect 정리의 close 이벤트가 새 팝업까지 닫음: 중복 onClose 상태 변경을 제거하고 기존 cancel 패턴 적용. 버튼과 실제 포인터 팝업 유지 재시험.
- 동시 변경 안내가 승인 시점에만 보임: 계획 비교로 즉시 승인 비활성, 입력을 유지한 최신 계획 재검토 제공. 이전 계획의 충돌 안내는 숨김.
- Escape 뒤 포커스가 문서로 이동함: 호출 버튼 복귀를 명시하고 버튼이 사라진 경우 계획 날짜로 복귀. Escape 후 호출 버튼 포커스를 확인.

자체 이벤트·포커스 처리 결함이며 Next.js 문제로 보고할 근거는 없다.

## 정리와 제한

- UI 장애·원격 변경은 임시 로컬 QA 프레임 모사이며 실제 API 시험과 구분한다. QA 종료 때 원본 계획 JSON 전체 일치, 업무0, 목표 불변, 이전 합성 시험 undo 제거를 확인했다. 원래 초안·테마 복원 후 QA 탭을 닫고 임시 HTML을 삭제했다.
- 실제 계정 시험은 signOut 후 해당 실행의 세션·사용자를 정리했고 `test_users_remaining=0`. 인증 fixture·SQL·생성 런타임 모듈 제거. 사용자 업무 계정을 사용하지 않았다.
- 운영 DB·Edge·Auth 설정 변경이 없다. 기존 사용자 미커밋 CSS·로고는 작업 범위 밖이다.
- 독립 사용자 사용성·실물 단말·실제 OAuth는 UX13/최종 사용자 확인 목록으로 유지한다. 브라우저 프레임 관측을 실제 휴대폰 검증으로 표시하지 않는다.
