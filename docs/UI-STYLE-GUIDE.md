# oddk 공통 UI 구조

## 현재 시간 개념

사용자 결정에 따라 **여유시간은 휴식시간을 포함**한다. 수행시간은 작업시간과 여유시간의 합계다.
예: 작업 50분 + 여유 10분(휴식 포함) = 수행 60분.
타이머는 실제 작업과 실제 휴식을 별도로 기록하며, 휴식 중에는 작업시간 집계를 멈춘다.
하루계획의 ALPEN 가이드는 제거했다. 과거 설명 중 여유와 휴식을 분리한 부분보다 이 정의를 우선한다.

## 목적과 범위

현재 화면과 데이터 처리는 유지하면서, 공통 수정 지점을 명확하게 만든다.
브랜드 재설계나 모든 화면의 수치를 일괄 변경하는 작업은 포함하지 않는다.

## 스타일 로딩

`app/todo/layout.tsx`만 `styles.css`를 가져온다. 컴포넌트에서 전역 CSS를 직접 가져오지 않는다.
`styles.css`가 로딩 순서를 명시한다.

1. `styles/tokens.css`: 공통 값과 라이트·다크 테마
2. `styles/foundation.css`: 글꼴, 본문 크기, 기본 행간
3. `todo.css`, `styles/controls.css`: 기존 화면 기본값과 공통 컨트롤
4. 기능별 CSS: 해당 기능에만 필요한 구조와 예외
5. `workspace-layout.css`: 작성 영역, 목록과 메뉴 등 현재 작업 화면
   `page-layout.css`는 페이지 공통 너비, 제목 영역과 본문 시작점만 담당한다.
6. `styles/states.css`: 선택·완료·진행·중요도의 상태 표현
7. `styles/daily-layout.css`: 시간표/목록 배치와 좁은 화면 전환

Next.js는 개발·빌드에서 CSS를 합칠 수 있으므로 컴포넌트 import 순서에 스타일 우선순위를 의존시키지 않는다.
스타일 변경은 개발 화면뿐 아니라 프로덕션 빌드에서도 확인한다.

## 무엇을 어디서 바꾸나

### 적용 규격

브랜드 블루 `#2454E6`, 연한 강조 `#EDF3FF`, 본문 `#243047`, 보조 `#657083`, 구분선 `#E4E8EF`를 사용한다.
보조 회색은 제안했던 `#687386`이 연한 배경에서 4.5:1에 미달해 조금 진하게 조정했다.
메인 소개 화면도 동일한 토큰을 가져오며 글꼴과 CTA 색상을 공유한다.

| 대상 | 공통 규격 |
| --- | --- |
| 화면 제목 / 영역 제목 / 본문 / 보조 | 24 / 16 / 14 / 12px |
| 기본 글자 굵기 | 400 / 500 / 600 |
| 본문 자간 / 제목 자간 | 0 / -0.02em |
| 본문 행간 | 1.6 |
| 기본 입력란·액션 높이 | 44px |
| 버튼·입력란 모서리 / 카드·팝업 모서리 | 6 / 8px |
| 기본 메뉴 아이콘 / 글자 간격 | 20 / 8px |
| 일반 간격 | 4 / 8 / 12 / 16 / 20 / 24 / 32px |

20px는 카드 안쪽 여백용으로 사용한다. 큰 소개 제목, 만다라트 자동 맞춤 글자, 시간표의 실제 시간 높이,
원형 아이콘·라디오·체크박스와 일정 구분용 파스텔 색상은 해당 역할에 필요한 예외다.
색상만으로 상태를 표현하지 않고 상태 문구를 유지한다. 다크 모드는 밝기와 글자 대비에 맞는 별도 토큰을 사용한다.

| 변경할 내용 | 수정 위치 |
| --- | --- |
| 주요 액션 색상 | `tokens.css`의 `--oddk-brand`, `--oddk-brand-hover` |
| 배경·글자·구분선 | `tokens.css`의 `--oddk-surface`, `--oddk-heading`, `--oddk-muted`, `--oddk-border` |
| 본문·보조·영역 제목 크기 | `tokens.css`의 `--oddk-font-*` |
| 공통 간격 | `tokens.css`의 `--oddk-space-*` |
| 공통 모서리 | `tokens.css`의 `--oddk-radius-*` |
| 기본 팝업 너비·여백 | `tokens.css`의 `--oddk-dialog-width`, `--oddk-dialog-padding` |
| 공통 팝업 필드·액션 버튼 높이 | `tokens.css`의 `--oddk-control-height`, `--oddk-button-height` |
| 메뉴 아이콘 크기·간격 | `tokens.css`의 `--oddk-icon-size`, `--oddk-icon-gap` |
| 시간표/목록 비율 | `tokens.css`의 `--oddk-plan-columns` |
| 시간표/목록 간격 | `tokens.css`의 `--oddk-plan-gap`, `--oddk-plan-divider-space` |

| 완료 카드·선택·상태 태그 색 | `tokens.css`의 완료·선택·성공·주의 토큰 |

예를 들어 `--oddk-plan-columns: repeat(2, minmax(0, 1fr))`를 바꾸면 넓은 화면의 비율이 바뀐다.
컴팩트 화면의 시간표 → 목록 순서와 화면 선택 동작은 그대로 유지된다.

## 담당 영역과 예외

### 페이지 공통 틀

- 하루계획·목표추적·하루점검·환경설정은 같은 `WorkspaceHeader`와 `oddk-pageBody`를 사용한다.
- 전체 최대 너비는 1600px이며 좌우 가운데로 정렬한다. 페이지별 840px·940px 제한은 제거했다.
- 데스크톱 상단 32px, 좌우 40px, 제목 24px, 제목 영역 최소 72px, 본문까지 24px를 공통 적용한다.
- 900px 이하 좌우 24px, 640px 이하 좌우 16px를 사용한다. 작은 화면의 제목 영역은 최소 88px이며 긴 설명은 잘리지 않고 늘어난다.
- 테마 버튼은 제목 오른쪽 공통 액션 영역에 둔다. 설명이 없어도 본문 시작점이 당겨지지 않는다.
- 스크롤바 공간을 확보해 긴 페이지와 짧은 페이지를 이동할 때 가로 정렬이 흔들리지 않게 한다.
- 값은 `tokens.css`의 `--oddk-page-*`, 실제 배치는 `page-layout.css`에서 관리한다. 기능별 CSS에서 페이지 틀을 덮어쓰지 않는다.

- `daily-layout.css` 이외 파일에 `.oddk-dailyGrid`, `.oddk-paneSwitch` 규칙을 추가하지 않는다.
- 공통 `.oddk-dialog`, `.oddk-dialogHeader`, `.oddk-dialogActions`, `.oddk-dialogField`, `.oddk-primary`는 `controls.css`에서만 정의한다.
- 개별 팝업의 크기·스크롤·버튼 배치는 `.oddk-taskEditor .oddk-dialogActions`처럼 기능 클래스 아래에서만 특화한다.
- 할 일 수정창의 긴 제목 입력, 만다라트 셀의 중앙 정렬, 시간표 셀 높이처럼 목적이 다른 규격은 공통화하지 않는다.
- `--edit-*`, `--settings-*`는 기존 컴포넌트와의 호환용 별칭이다. 실제 테마 값은 공통 토큰을 참조한다.
- 상태 색은 텍스트 의미와 함께 사용한다. 선택한 완료 카드는 선택 배경이 우선한다.
- `DialogHeader`는 제목·닫기 버튼만 담당한다. 열기·닫기 상태, 포커스 복원, 충돌 검사, 저장 로직은 각 팝업이 유지한다.
- 기능별 CSS에는 해당 기능의 구조만 추가하고, 공통 규칙을 다른 파일 끝에서 재정의하지 않는다.

## 검사와 검증

`npm run lint:styles`는 CSS 구문, 전체 스타일 연결 누락, 중복 import, 순환 import,
전역 CSS 진입점 분산, 공통 토큰의 중복 선언, 없는 토큰 참조, 레이아웃 담당 영역 침범을 검사한다.
일반 `npm run lint`에도 포함되어 있다.

ALPEN 점검 흐름:

- **A**: 변경하려는 UI와 영향 화면을 확인한다.
- **L**: 공통 토큰·공통 컨트롤·기능 예외 중 수정할 담당을 정한다.
- **P**: 긴 내용, 빈 화면, 다크 모드, 작은 화면의 예외를 확보한다.
- **E**: 담당 파일에서 수정하고 중복 덮어쓰기를 추가하지 않는다.
- **N**: 타입·린트·단위 테스트·빌드 후 실제 브라우저에서 확인한다.

브라우저 확인 항목:

- 하루계획: 시간표 왼쪽/목록 오른쪽, 50:50, 완료 회색, 선택 하늘색
- 좁은 화면: 시간표 → 목록 버튼 순서, 선택한 영역만 표시, 가로 넘침 없음
- 첫 화면: 하루계획 선택, 다른 메뉴에서 새로고침해도 하루계획 표시, 기존 입력·초안 보관
- 하루점검: 메뉴 선택 표시, 날짜 선택·오늘 이동, 날짜별 점검과 저장 버튼
- 목표추적: 셀 정렬·목표 입력·연결된 할 일 상태
- 환경설정: 탭 전환과 테마 전환
- 팝업: 제목·닫기·취소·저장, Escape, 포커스 복원, 비활성화와 오류 표시

## 남겨둔 범위

기능별 레이아웃과 과거 기능 스타일 전체를 강제로 하나의 컴포넌트로 합치지는 않는다.
여행·알펜·반복 일정 등의 기능별 스타일은 기존 파일을 유지한다.
정적 구조 검사는 시각적 회귀나 접근성 검증을 대신하지 않는다.

## 하단 고정 작업 타이머

`ExecutionPanel`은 화면별 숨김 영역 밖에서 한 번만 렌더링된다. 작업 기록이 있으면
`execution-dock.css`가 하단 고정 바를 표시한다. 메뉴 전환은 기록을 중단하거나 새로 시작하지 않는다.

- 큰 타이머는 누적 작업시간만 시:분:초로 표시한다. 휴식 중에는 큰 타이머가 멈추고 별도의 휴식시간만 증가한다.
- 작업으로 복귀하면 기존 작업시간부터 이어서 집계하며, 일시정지는 작업·휴식 집계 모두에서 제외한다.
- 기록이 있는 동안 다른 작업 시작은 UI와 시작 핸들러 양쪽에서 차단한다.
- 일시정지·휴식 중에도 시작 잠금을 유지하며, 기록 종료 후 해제한다.
- `--oddk-sidebar-width`를 앱 셸과 고정 바가 공유한다. 모바일에서는 전체 폭을 사용한다.
- `ResizeObserver`로 실제 바 높이를 측정해 하단 여백을 확보한다. 긴 제목·모바일 줄바꿈에도 대응한다.
- 타이머를 초마다 스크린리더에 강제로 알리지 않는다. 기존 저장 실패·재시도 처리는 유지한다.

검증: 단위 테스트 323개, 타입·린트·빌드 통과. 별도 로컬 테스트 환경에서
시작 → 다른 시작 버튼 잠금 → 네 메뉴 이동 → 새로고침 복원 → 일시정지 → 휴식 → 종료 → 잠금 해제 → 다른 작업 시작 확인.
390px에서 고정 바의 왼쪽 0px, 실제 높이 약 153px에 대해 하단 여백 약 169px 확보 및 종료 후 제거 확인.

## 종료 기록 조회

기록 종료는 기존 저장 트랜잭션이 완료된 뒤 성공 처리한다. 종료 후 대시보드 항목에 최근 실제 작업·휴식 시간을 표시하며,
지금 할 일 제목 옆 ‘수행 기록’에서 오늘 실제 수행한 기록을 조회할 수 있다.
기록은 계획 시간과 별개이며 할 일 완료 상태를 자동으로 바꾸지 않는다.
종료 기록의 계산 기준은 저장된 종료 시각이므로 시간이 지나도 값이 증가하지 않는다.

검증: 단위 테스트 325개, 타입·린트·빌드 통과. 별도 브라우저 저장소에서 기존 3개 기록을 확인하고
새 작업 종료 후 4개로 증가한 것을 확인했다. 새로고침 후에도 기록 개수, 시작·종료 시각, 작업 23초가 동일했다.
실제 계정의 OAuth·서버 동기화 검증은 이 로컬 저장소 검증에 포함하지 않았다.

- 대시보드 하위 작업이력에서 조회 날짜별 종료된 수행 기록과 시작/종료/작업/휴식 시간을 확인한다. 하루계획의 수행 기록 버튼은 제거했다.
- 기존 실행 API와 IndexedDB 저장소를 재사용하고 계정/날짜 전환 시 이전 조회 결과를 숨긴다. 타이머는 메뉴 이동 중에도 유지한다.
- 검증: typecheck, lint(경고 없음), 단위 테스트 319개, production build 통과. 독립 로컬 3203에서 기록 종료 직후 반영, 재조회, 새로고침 후 보존, 기록 없는 날짜, 모바일 390px 배치를 확인했다. 실제 OAuth 및 원격 계정 검증은 수행하지 않았다.
- 일정 안내 X 닫기는 항목을 삭제하지 않으며 동일 조건에서 메뉴 이동 후에도 닫힌 상태를 유지한다.
