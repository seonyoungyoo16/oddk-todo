# 로컬 AI로 할 일 나누기

하루계획의 **추가** 또는 Enter는 입력을 한 건의 할 일로 바로 저장한다. 로그인·AI·네트워크가 필요하지 않다. 제목은 앞 120자까지 사용하고, 긴 입력의 전체 원문은 상세 메모에 보관한다. 여러 줄도 기본 추가에서는 한 건으로 취급한다.

**AI 분석**은 선택 기능이다. 로컬 PC에서는 Ollama `qwen3:4b`, 배포 웹·모바일에서는 로그인한 사용자의 AI 게이트웨이가 입력을 의미 단위로 나눈다. 결과가 한 개여도 제목 수정·항목 제외가 가능한 확인창에서 사용자가 추가를 눌러야 저장한다.

- 원문: 최대 2,000자. 나눈 결과: 최대 32개, 제목별 120자.
- AI 결과는 개수와 관계없이 확인 전에는 목록에 저장하지 않는다. 취소·연결 실패·중복 오류가 나면 원문을 유지하고 일반 추가를 사용할 수 있다.
- 시간·중요도는 자동 추정하지 않는다. 명시된 조건은 제목에 남기고, 실제 일정은 기존 수정창에서 설정한다.
- 같은 날짜에 같은 제목으로 남아 있는 할 일은 중복 추가하지 않는다.
- 나누는 중에는 중단할 수 있다. 화면이나 계정이 바뀌면 해당 요청을 취소한다.

## 실행 조건

로컬 AI 분석에는 Ollama가 `http://127.0.0.1:11434`에서 실행 중이고 `qwen3:4b`가 설치돼 있어야 한다. 모델 확인은 `GET /api/tags`로 할 수 있다. 일반 추가에는 Ollama가 필요하지 않다.

로컬 앱은 `http://localhost:3200/todo` 또는 `http://127.0.0.1:3200/todo`처럼 같은 PC의 주소에서 연다. 배포 웹·네이티브 앱은 기기 자신의 localhost에 있는 Ollama를 호출하지 않고 인증된 게이트웨이를 사용한다. 일반 추가와 계정 동기화는 별도이며, 로그인한 계정의 저장 변경은 기존 동기화 정책을 따른다.

## 검증

- `npm.cmd test`: 분리 응답 검증, 원자적 일괄 추가, 중복·ID·분류 오류, 잘린 AI 응답, 외부 호스트 차단.
- `tests/local-ai-browser.tsx.template`: 임시 `app/local-ai-qa/page.tsx`로 복사해 별도 `localhost:3201`에서 실행하는 실제 Qwen 회귀 검사. 기존 계획·로그인이 있는 저장소는 거부하고 원본 보관 후 합성 데이터만 사용한다. 검사 후 Restore storage를 누르고 임시 경로를 제거한다.
- 실제 Qwen 예문과 브라우저에서 결과 수정·제외·일괄 저장·새로고침 유지·중복 거부·취소 시 원문 보존을 확인했다.

JSON 구조와 길이는 코드가 검증하지만 의미 분리는 모델이 틀릴 수 있으므로 사용자 확인 단계를 유지한다.

## 첫 전송 동의

AI 분석을 처음 선택하면 실제 수신자·전송 항목·모델·로그 보관의 확인 범위를 안내하고 명시 동의를 받습니다. 기기·계정·처리조건/문구 버전별 동의 저장을 확인한 뒤 전송합니다. 설정 → 계정·동기화 → AI 분석·동의에서 확인·철회할 수 있습니다. 철회/계정전환/삭제중/원문변경은 요청과 늦은 결과 적용을 막으며, 일반 추가는 계속 사용할 수 있습니다. 이미 전송한 내용 회수·외부 로그 즉시 삭제를 약속하지 않습니다.
