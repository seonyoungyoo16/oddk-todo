# T09 인증·동기화 인수시험

상태: **사용자가 OAuth 검증을 보류한 배포 범위의 검증 완료 / 배포 확인 대기**. OAuth 실제 로그인 완료로 기록하지 않는다.

기준 코드: T08 배포 `75c6a4d4ef04308b79e30c9eb0f68339fc1755b6`, Edge `plan-sync` version5. 2026-10-27 KST에 실행했다. 사용자의 각 단계 배포 규칙에 따라 T09 완료·배포 전 T10을 시작하지 않는다.

## 환경과 자료

- Windows, Node24, Next16.4.3, React19.3.0. IAB와 Chrome의 독립된 브라우저 저장소 두 곳을 사용했다. Chrome 프로필 자체를 새로 생성한 것은 아니며 두 물리 기기 시험도 아니다.
- 실제 사용자 계정 대신 `prepare-account-fixture.mjs`의 일회용 계정 두 개만 사용했다. 테스트 비밀번호 방식으로 로그인했으며 OAuth 성공을 대신하지 않는다.
- 양쪽 브라우저의 비로그인 원본을 로컬에 보관하고 빈 계획에서 시작했다. 원본 데이터는 서버 시험 자료로 전송하지 않았다. 종료 후 브라우저 원본 복원, 시험 로그인 종료, 임시 QA 경로 삭제를 확인했다.
- 운영 CORS가 검증용3100을 거부하므로 허용 범위를 확장하지 않았다. 기존3000 서버를 잠시 작업본 서버로 교체해 시험하고 원래 소스의3000 서버를 재시작했다. 작업본은3100으로 복귀했다. 원본 page/sync-store/task-editor CSS 해시는 시작 시점과 동일하다.

## 사용자 보류와 배포 범위

- Google: 별도 테스트 계정으로 로그인 시작 → 제공자 인증 → 콜백 → 앱 복귀 → 계정 데이터 반영.
- GitHub: 동일한 전체 OAuth 여정. 기존 실제 업무 계정으로 대체하지 않는다.
- 사용자는2026-10-27 "지금은 실제 OAuth 검증을 보류할게요"를 선택했다. 두 제공자의 실제 OAuth는 이번 완료 배포 범위에서 제외한다.
- 명세에 따라 Google/GitHub 로그인 버튼을 준비 중/비활성으로 표시하고 loginSync 진입점도 차단했다. 기존 공급자 설정과 로그인한 계정의 동기화·로그아웃 동작은 보존했다. 계정이 없는 사용자는 기기에 저장한다.
- 단위시험39개 통과. 보류된 로그인 호출이 인증 요청이나 캐시 변경을 시작하지 않는 시험을 추가했다. lint/typecheck/정적 빌드 통과.
- 추가 실제 브라우저 시험: 별도 localhost3111의 일회용 계정으로 동기화 통신 실패를 주입했다. waiting 상태에서 날짜별 점검을 보관한 뒤 시험 탭 종료→새 탭 재접속→synced를 확인했다. 차단 중 서버version1/점검 없음, 재접속 후version2/동일 점검을 DB와 대조했다.
- 이는 실제 브라우저 localStorage와 새 페이지 실행을 사용했지만 회선 차단이나 전체 브라우저 프로세스 종료 시험은 아니다. 계정 데이터 없는 별도 origin과 테스트 전용 로컬 중계를 사용했고 중계·임시 페이지·fixture·사용자(잔여0)를 제거했다. 운영 CORS 변경 없음. 증거 `evidence/T09-offline-waiting.jpg`, `T09-offline-reopened.jpg`.
- 자연 JWT 만료를 기다린 시험은 하지 않았으며 실제401 응답에서 보존/복구한 범위를 유지한다. 물리 기기, 회선 단절, 브라우저 전체 종료의 환경 검증은 잔여로 기록한다.

두 제공자의 실제 OAuth는 완료로 표시하지 않는다. 이후 실제 OAuth 인수시험을 통과하면 OAUTH_READY와 준비 중 UI를 함께 변경해 별도 검증·배포한다. 이번 PR은 사용자 보류 결정과 준비 중 UI를 반영한 뒤 배포하고 정상 확인 후T10으로 진행한다.

ALPEN: 집중90분+예비30분 배정. 실제 집중 시간을 별도 계측하지 않았다. 외부 대기 뒤 사용자의 보류 결정을 반영했다. T10/T11은 이 배포 정상 확인 후 진행한다.
