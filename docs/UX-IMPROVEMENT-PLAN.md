# oddk UX 개선 작업계획

작성일: 2026-10-28 · 기준 시간대: Asia/Seoul  
상태: **구현 승인 / UX00 기준선·설계 확인 / 배포 게이트 진행 중**

이 문서는 사용자 평가를 바탕으로 기획·QA 관점의 개선 범위, 우선순위, 의존성, 완료 조건을 정리한다. 문서 작성은 앱 코드 수정, DB 변경, 외부 서비스 연결, 배포의 승인이 아니다. 실제 구현은 후속 지시를 받은 뒤 단계별로 진행한다.

## 1. 목표와 적용 범위

핵심 목표: **할 일을 적고 날짜에 배치하면 오늘 할 일과 사용 가능한 시간이 한눈에 보이게 한다.**

- 사용자가 ALPEN·만다라트의 이름을 몰라도 기본 계획을 만들 수 있어야 한다.
- 목록, 시간표, 목표가 같은 할 일을 서로 다르게 보여준다는 관계를 명확하게 한다.
- 빠른 메모는 날짜·시간 없이 허용하고, 실제 일정은 날짜와 시간으로 구체화한다.
- 입력 유실·예상하지 않은 일정 변경을 막고 변경 결과와 복구 방법을 보이게 한다.
- 시간 합계는 계획값이다. 실제 시간 기록을 도입하기 전에는 실적처럼 표현하지 않는다.

작업 대상은 `C:\workspace\study\todo`다. 기존 `CODEX-TASKS.md`의 T00–T11 안정화 이력은 보존하고, 이번 개선은 별도 ID `UX00`부터 추적한다. `C:\workspace\react_todo\todo`는 이번 구현 대상에 포함하지 않는다.

Google·GitHub 로그인은 사용자 요청으로 재활성화했다. 실제 로그인 검증은 사용자가 별도로 수행한다. 이 문서의 미실행 OAuth 시험을 이유로 로그인 기능을 다시 비활성화하지 않는다. 기존 인증 설정과 사용자 데이터를 임의 변경하지 않는다.

아래는 직전 소스 확인에 기반한 기준선이며 새 QA 통과 결과가 아니다. UX00에서 최신 버전을 다시 확인한다.

| 여행 이동 시간 조회 | 추가 필요 | 작은 시제품으로 유용성·정확도·운영 조건 검증 |

## 3. 정보 구조와 기본 설계안

다음은 **구현 전 검토할 제안 기본안**이다. 아직 확정된 사용자 요구나 구현 완료 동작이 아니다.

| 축 | 제안 | 이유 |
|---|---|---|
| 날짜 범위 | 오늘 / 이번 주 / 전체 할 일 | 일간 계획과 주간 탐색 연결 |
| 카테고리 | 업무 / 개인 / 자기계발 등 사용자 관리 분류 | 어떤 종류의 일인지 구분 |
| 보기 방식 | 리스트 / 시간표 | 같은 계획의 다른 표현. 카테고리와 혼합하지 않음 |
| 목표 | 목표 → 세부 목표 → 연결한 할 일 | 목표와 실행 관계를 한눈에 확인 |
| ALPEN | 오늘 계획의 입력·시간 예상·여유·선택·점검 흐름 | 독립 탭의 학습 부담 축소 |
| 시간통계 | 오늘 화면의 간단 요약 + 펼쳐 보는 상세 분석 | 기본 화면에서 계획 가능량 판단 |

- 카테고리는 할 일당 하나(미분류 허용), 태그는 여러 개를 기본안으로 한다. 카테고리 삭제 시 할 일을 삭제하지 않는다.
- 날짜 필터와 카테고리·태그 필터를 함께 적용한다. 서로 다른 카테고리의 일정 충돌도 알 수 있게 한다.
- 넓은 화면은 목록·시간표를 함께, 좁은 화면은 같은 날짜·필터를 유지한 보기 전환을 기본안으로 한다. 모든 기능을 동시에 펼치지 않는다.
- 소개 화면은 `할 일 수집 → 날짜 배정 → 시간 배치 → 목표 연결 → 하루 점검`의 예시를 제공하고 각 화면으로 이어지게 한다.

### 시간·상태·순서 계약

1. 시작·종료 입력 시 **수행 시간 = 종료 − 시작**, **작업 시간 = 수행 − 여유**로 계산한다. 종료에는 여유가 포함된다.
2. 예: `09:00~10:00 · 총60분 = 작업50분 + 여유10분`. 여유를 종료 시각 뒤에 중복 가산하지 않는다.
3. 날짜 없는 할 일, 날짜만 있는 할 일을 허용한다. 시간표 배치를 위해서만 유효한 시간 설정을 요구한다.
4. 자정 넘김은 종료 날짜를 명시한다. 종료가 시작보다 이르다는 이유만으로 다음 날로 임의 추정하지 않는다.
5. 초기 개선에서는 현재 시간 상한240분과 양수 여유 규칙을 유지한다. 장시간 일정·여유0 허용은 UX00에서 별도 결정한다. UI만 바꾸고 서버 규칙을 우회하지 않는다.
6. 긴급도는 선택한 마감에서 계산하고 중요도는 사용자가 지정하는 방안을 우선 검토한다. 기존 높음/보통/낮음 값을 자동으로 새로운 중요도로 해석하지 않는다.
7. 수동 정렬과 중요도·마감 정렬을 구분한다. 드래그는 수동 순서 모드에서 제공하고 시간표 드래그는 시각 변경임을 알린다.
8. 오늘 남은 시간은 사용자가 정한 활동 가능 구간과 고정 일정·휴식·이동을 고려한다. 전체 계획 분 합계와 겹침을 제거한 점유 시간은 구분한다.

### 단계 0 — UX00: 기준선과 결정사항

- 아래 미결정 사항의 기본안을 검토하고 선택 결과와 이유를 기록한다.
- 새 필드는 브라우저·서버·검증기·백업·구버전 클라이언트까지 함께 설계한다. 현재 V2를 조용히 재해석하지 않는다.

완료 조건:

- [ ] 현재 배포 SHA·소스·Edge/DB 구성을 확인하고 기존 기능의 실제 동작을 재현했다.
- [ ] 초안 범위, 시간 계약, 주간 범위, 분류·정렬 정책을 문서에 확정했다.
- [ ] 데스크톱/모바일 시안에서 날짜 선택→등록→시간 배치→목표 연결 흐름을 설명할 수 있다.
- [ ] 새 데이터의 이전·검증·복구·구버전 쓰기 정책이 있다.

### 단계 1 — UX01~UX02: 입력과 저장

- 할 일 추가·수정·목표·점검의 미저장 입력을 사용자/계정/대상별로 보존한다. 초안을 자동으로 확정 업무로 등록하지 않는다.
- 저장 중/저장됨/실패 및 복구할 초안의 대상·시점을 알린다. 명시적 취소·등록 성공·로그아웃 시 초안 처리 규칙을 통일한다.
- 제목은 여러 줄로 자동 확장하고 상세 메모를 별도로 둔다. 제목 상한120자는 우선 유지하고 메모 상한은 UX00에서 정한다. 기존 상한 초과 입력을 조용히 자르지 않는다.
- 삭제·완료 직후 공통 실행 취소를 제공한다. 삭제 복구 시 날짜·시간·순서·목표 연결을 함께 복원한다.

완료 조건:

- [ ] 화면·카테고리·날짜 이동 및 새로고침 후 해당 초안이 복구되고 확정 업무 중복이 없다.
- [ ] 다른 계정이나 비로그인 공간에 이전 계정 초안이 노출되지 않는다.
- [ ] 저장 공간 부족·저장 실패 후 입력이 남고 재입력 없이 재시도할 수 있다.
- [ ] 긴 문장·줄바꿈·한글 조합 입력에서 커서와 높이가 정상이고 모바일 저장 버튼이 가려지지 않는다.
- [ ] 삭제·완료 실행 취소의 적용 범위·유효 기간이 명확하고 복구 전후 데이터가 일치한다.

### 단계 2 — UX03~UX04: 날짜 중심의 하루 계획

- 날짜 선택 상태에서 바로 할 일을 등록한다. 전체 할 일에는 날짜 없는 메모도 남긴다.
- 상태는 완료 체크로 표현하고, 등록 시 별도 상태 선택을 강요하지 않는다. 날짜는 선택한 달력 문맥에서 이어받고 수정 화면에서는 필요할 때 변경한다.
- 오늘/주간 탐색, 리스트/시간표 전환, 오늘의 합계를 연결한다. 주간 화면에서 날짜를 선택하면 해당 날짜로 이동한다.
- ALPEN·통계 독립 메뉴 축소 및 목표 화면과의 관계를 소개 화면에 설명한다. 기존 기능을 단순히 삭제하지 않는다.
- 시작/종료·여유 입력을 시간 계약에 맞춰 계산하고 겹치는 일정·활동 가능 구간 초과를 표시한다. 확정 일정은 자동 이동하지 않는다.

완료 조건:

- [ ] 선택 날짜에 등록되고 오늘·이번 주·전체 및 목표 연결 화면에서 같은 ID의 업무가 보인다.
- [ ] 오늘과 내일 합계가 섞이지 않고 날짜 없는 업무는 일별 합계에서 빠진다.
- [ ] 09:00~10:00/여유10분 입력은 수행60/작업50/여유10으로 모든 화면에서 일치한다.
- [ ] 유효하지 않은 순서·날짜·시간, 자정 넘김, 상한 경계를 UI와 서버가 같은 규칙으로 처리한다.
- [ ] 연속 일정은 충돌이 아니며 실제 겹침은 양쪽 대상을 알린다. 카테고리 필터로 숨긴 일정과의 충돌도 놓치지 않는다.
- [ ] 소개만 읽고 기법 이름을 모르더라도 첫 업무 추가→날짜 배정→시간표 확인을 수행할 수 있다.

### 단계 3 — UX05~UX07: 분류·찾기·목표

- 카테고리 추가/이름/색상 변경, 태그 연결/해제, 검색 및 필터 해제를 제공한다.
- 같은 필터를 보기 전환에도 유지하고 현재 범위·결과 개수를 보여준다. 색상 외에 이름·아이콘 등 구분 수단을 둔다.
- 중요도·마감·정렬을 구분하고 번호는 현재 표시 순서임을 명확하게 한다. 선택한 업무와 숨겨진 업무의 처리 범위를 알린다.
- 목표 트리는 우선 핵심 목표→가변 개수 세부 목표→업무의 3단계로 검토한다. 무제한 깊이·협업 편집은 별도 범위다.
- 큰 업무를 여러 실행 업무로 나눠 같은 세부 목표에 연결할 수 있게 한다. 세분화 후 원래 업무를 유지할지 대체할지, 시간 합계를 어떻게 처리할지는 UX00에서 정하고 부모·자식 시간의 중복 합산을 막는다.
- 기존 8×8 만다라트 연결을 보존한다. 가변 트리를 만다라트로 표시할 수 없는 경우 자르지 않고 별도 보기와 제한을 안내한다.

완료 조건:

- [ ] 예시 #운동 필터는 해당 태그가 연결된 업무만 보여주며 제목의 단순 부분 문자열과 혼동하지 않는다.
- [ ] 분류 삭제는 업무를 보존하고 미분류로 이동한다. 필터 초기화로 전체 목록에 돌아갈 수 있다.
- [ ] 정렬을 바꿔도 저장된 수동 순서·시간·ID가 임의로 바뀌지 않는다.
- [ ] 날짜가 다른 선택 업무만 일괄 처리하고 숨겨진 선택의 포함 여부를 실행 전에 알린다.
- [ ] 목표·세부 목표·업무 제목이 함께 보이고 완료 업무는 체크와 흐린 글자로 구분된다.
- [ ] 세부 목표 추가/삭제 후 연결 업무가 사라지지 않는다. 기존 목표·연결의 이전 및 복구를 확인했다.

### 단계 4 — UX08: 여행 이동 시간 제안 시제품

첫 범위는 **출발/도착 장소·방문 순서·출발 시각·이동 수단 입력 → 이동 시간 조회 → 이동 구간 제안 → 사용자 확인 후 반영**이다. 서비스 선정 전 비용·한도·허용 데이터·정확도·장애 대응을 확인한다. 유료 연결과 외부 전송은 구현 승인 범위를 별도 확인한다.

- 조회한 이동 시간, 사용자가 정한 활동 시간, 시스템 추정 시간을 구분한다.
- 마사지·관광 등의 활동 시간을 확정값처럼 자동 채우지 않는다. 출처와 가정이 있는 제안만 제공한다.
- 처음부터 여행 전체 자동 검색·예약·최적화는 하지 않는다. 조회 실패·장소 모호성 시 직접 입력할 수 있게 한다.

완료 조건:

- [ ] 장소·이동 수단·출발 조건에 맞는 조회 결과와 출처/조회 시점을 보여준다.
- [ ] 승인 전 일정 데이터가 바뀌지 않고 반복 적용해도 이동 구간이 중복 생성되지 않는다.
- [ ] 수동 수정값을 재조회가 조용히 덮지 않는다. 실패·한도 초과 시 기존 계획을 보존한다.
- [ ] 실제 여행 예시의 수동 계획 대비 절약한 입력 단계·시간, 부정확한 제안·수정 횟수를 기록한다.
- [ ] 비교 결과로 확대/수정/중단을 결정한다. 단순 API 연결을 유용성 검증 완료로 처리하지 않는다.

### 단계 5 — UX09~UX12: 실행 지원 확장

- UX09: 목록 드래그는 순서, 시간표 드래그는 시작/종료 시각 변경이다. 키보드·버튼 대체 조작과 실행 취소를 제공한다.

- UX11: 시작/일시정지/재개/종료 및 수동 보정을 제공한다. 계획값은 유지하고 작업 실적·휴식 기록을 구분한다. 기록 중 새로고침·다른 기기 조작·중복 타이머 정책을 정한다.

## 6. ALPEN 작업 블록과 진행 규칙

확정 일정을 예약하지 않는다. 아래는 구현 승인 후 사용하는 추정 단위이며 실제 속도는 UX00 결과로 조정한다.

- A: 각 UX 작업을 구현/이전/시험/정리의 작은 산출물로 나눈다.
- L: 한 집중 블록은 작업50분+검증·수정 여유15분으로 잡는다. 여러 블록에 걸치면 중간 결과를 남긴다.
- P: 블록의 여유15분과 별도로 CI·외부 API 승인·사용자 검증 대기를 기록한다. 대기를 집중 시간으로 계산하지 않는다.
- E: P0 → P1 → P2 순서로 진행하되 UX08은 P1 가치 검증 블록을 확보한다. P2 확장 때문에 핵심 화면 개선을 미루지 않는다.
- N: 매 블록 말에 완료 조건, 실패 시험, 실제 소요 시간, 다음 행동을 점검한다.

|---|---|---|
| 0 | 현황 재현 → 설계/데이터 결정 → 시안 검토 | UX00 완료 조건 |

## 7. 구현 전에 결정하고 기록할 사항

1. 주간 시작 요일, 활동 가능 시간 구간과 개인 휴식·고정 일정의 포함 방식.
2. 종료 날짜 입력 방식, 장시간 일정 상한과 여유0 허용 여부.
3. 초안의 명시적 취소·로그아웃·계정 전환 처리와 보존 기간, 기기 간 공유 여부(초기 제안: 해당 브라우저 내 계정별 보존).
4. 중요도·마감 필드와 기존 priority 이전 방식, 수동 순서의 저장 범위.
5. 메모 상한, 카테고리·태그 상한/이름 중복/AND·OR 필터 규칙.
6. 가변 목표 개수 상한과 만다라트 보기 호환 범위. 목표 삭제 시 연결 해제 확인 방식.
7. 이동 시간 서비스·비용 상한·외부 전송 범위와 시제품 성공 기준. 시험 전에 비교 과제와 목표치를 정한다.
8. 반복의 시간대·월말 정책, 알림 대상 환경과 서버/브라우저 전달 방식.
9. 실적 기록의 중복 타이머·다른 기기 조작 정책, 재조정에서 이동할 수 없는 일정의 정의.
